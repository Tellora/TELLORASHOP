# Deployment & Subdomain Setup Guide for TELLORASHOP

This guide explains how to deploy **TELLORASHOP** and link it to your custom subdomain: **`shop.telloramediahq.com`**.

---

## 1. Why GitHub Pages Fails & What to Use Instead

GitHub Pages is designed strictly for static HTML sites. TELLORASHOP is a full-stack Next.js application that uses:
- Server-Side Rendering (SSR)
- API Routes (`/api/orders`, `/api/products`, etc.)
- Authentication & Sessions (`bcryptjs`, `jose`)
- SQLite Database (`better-sqlite3` reading/writing `tellorashop.db`)

To run this app on GitHub, you need to host it on a Node.js-compatible platform such as **Vercel** or a **Cloud VPS / Container host (Render, Railway, DigitalOcean, Hetzner, AWS)** using the provided GitHub Actions workflow and Dockerfile.

---

## 2. Host Option A: Vercel (Easiest & Free)

Vercel is the official platform built by the creators of Next.js.

### Step 1: Connect your GitHub Repo to Vercel
1. Go to [vercel.com](https://vercel.com) and log in with your **GitHub account**.
2. Click **"Add New..."** -> **"Project"**.
3. Import your GitHub repository: **`Tellora/TELLORASHOP`**.
4. Framework Preset will automatically detect **Next.js**.
5. Click **"Deploy"**.

### Step 2: Add your Subdomain (`shop.telloramediahq.com`) on Vercel
1. In your Vercel Project Dashboard, go to **Settings** -> **Domains**.
2. Type `shop.telloramediahq.com` and click **Add**.
3. Vercel will show the required DNS record for your domain registrar:
   - **Type**: `CNAME`
   - **Name / Host**: `shop`
   - **Target / Value**: `cname.vercel-dns.com`

---

## 3. Host Option B: Render / Railway / VPS (Docker)

If you prefer self-hosting with persistent local SQLite (`tellorashop.db`):

### Step 1: Deploy with Docker
1. Push your repository to GitHub.
2. In **Render**, **Railway**, or your **VPS (e.g. via Portainer / Coolify)**, select **New Web Service** and select `Tellora/TELLORASHOP`.
3. Choose **Dockerfile** as the build environment (the included `Dockerfile` will automatically build the standalone container).
4. Set port to `3000`.

### Step 2: Configure DNS for VPS / Render
In your DNS provider (Cloudflare / Namecheap / GoDaddy):
- **For Render / Railway**:
  - **Type**: `CNAME`
  - **Name / Host**: `shop`
  - **Value**: `<your-app-subdomain>.onrender.com` (or Railway URL)
- **For Custom VPS (DigitalOcean / Hetzner / AWS)**:
  - **Type**: `A`
  - **Name / Host**: `shop`
  - **Value**: `<YOUR_SERVER_PUBLIC_IP>`

---

## 4. DNS Configuration Summary for `shop.telloramediahq.com`

Log in to the DNS provider where `telloramediahq.com` is managed (e.g., Cloudflare, Namecheap, GoDaddy):

| Record Type | Name / Host | Target / Value | Purpose |
| ----------- | ----------- | -------------- | ------- |
| **CNAME** | `shop` | `cname.vercel-dns.com` | If using Vercel |
| **CNAME** | `shop` | `your-app.onrender.com` | If using Render |
| **A** | `shop` | `123.45.67.89` | If using direct VPS IP |

> **Note**: SSL certificates (HTTPS) are automatically generated by Vercel, Render, or Cloudflare once the DNS record propagates (usually takes 1–10 minutes).

## 5. GitHub Actions Workflow

The repository includes `.github/workflows/deploy.yml`. Every time you push changes to `main`:
- GitHub Actions automatically runs linter and verifies the Next.js build.
- You can optionally set GitHub Repository Secrets (`VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`) to trigger automatic production deployments on every push.

## Going live checklist

1. **Environment variables**: copy `.env.example`, fill it in and set the values in your host. `JWT_SECRET` is required in production.
2. **Change the admin password**: log in as the seeded admin, open My Account > Security and set a new password. The admin panel warns you until you do.
3. **Remove demo data**: the seeded demo customer, sample orders and sample products are fake. Delete them in the admin panel (or start from a fresh database).
4. **Store Settings**: open Admin > Store Settings and fill in your store details, shipping, tax and payment methods. The "Launch readiness" box shows what is still missing.
5. **Legal pages**: review and edit Privacy Policy, Terms of Service and the other pages in Admin > Pages. The defaults are templates.
6. **Database persistence**: the app stores everything in `tellorashop.db` (SQLite). It must live on a disk that persists between deploys (a VPS or a Docker volume). Serverless hosts such as Vercel have a read-only, temporary file system and will lose data.
7. **Back up** `tellorashop.db` regularly.
